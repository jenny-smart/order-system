# 成立訂單共用流程

單筆入口以 `booking_flow.py` 的付款契約及同一套會員／地址／計時／班表／送單核對流程為準；批次維持既有下拉地址與多時段送單實作。程式不自行呼叫 Google Maps、不借用其他地址的區域資料，也不猜 `area_id` 或 `company_id`。

## 固定流程

1. 選購買項目。
2. 以手機查會員。查無會員時，必須先取得姓名與 Email 並建立會員；查到會員則沿用後台會員資料。
3. 舊客先比對地址下拉選單；有相同地址時必須選該 `addressId`，讓後台帶入該地址的區域與客服備註，不得再直接輸入地址。只有下拉沒有該地址時，才依輸入地址選縣市、鄉鎮市區及填寫新地址，再操作後台原生「查詢地區」。後台未回傳服務區域就停止。
4. 填坪數、打掃區域或需求，操作「計算時數」。保留使用者最後指定的人數／時數，不擅自改成系統建議值。
5. 用最後指定的人數、時數查班表。
6. 只選後台實際回傳的日期／時段。查無原時段就停止；只有入口明確允許自動補班時，才去專員班表補檸檬人並重新查詢。
7. 信用卡／ATM 選付款方式；儲值金固定為 `payway=4`。
8. 信用卡／ATM 必選發票類別：捐贈、個人二聯或三聯。
9. 二聯式必選會員載具、手機載具、自然人憑證或紙本；三聯式必填抬頭與統編；捐贈必填捐贈碼。
10. 有優惠碼才填。送出後，必須找到唯一符合本次手機、地址、日期、時段與付款方式的新訂單編號才算成功。

儲值金頁可一次送多個 `date_list[]`；信用卡／ATM 頁一次只能送一個 `datePeriod`。儲值金回覆 `count > 0` 代表有未成立訂單（通常為餘額不足），不能視為成功。

## 入口整合

| 入口 | 共用核心 | 入口專屬處理 |
|---|---|---|
| 舊客成單 | `quick_create_order` | 查既有會員與地址 |
| 新客成單 | 建立會員後呼叫 `quick_create_order` | 拆姓名、手機、Email、地址與發票 |
| 保留單 | `quick_create_order` | 保留率、人力安全門檻、成立後備註 |
| 訂單轉換 | 每張新單呼叫 `quick_create_order` | 原單處理、優惠券與金額核對 |
| 儲值金補差價 | 兩階段都呼叫 `quick_create_order` | 儲值金清零單與一般付款差額單 |
| 批次成單 | 維持原本 `orders.process_one_group` | 原有 `addressId` 下拉地址、儲值金多時段 checkbox、逐列回填與一致性檢查均不變 |

付款入口只有兩個：信用卡／ATM 走 `/booking/single`；儲值金走 `/booking/stored_value_routine`。其他步驟不得因入口不同而另寫判斷或猜資料。

## 補充規則

- 地址開頭的郵遞區號（例如 `108臺北市…`）會在對應縣市／鄉鎮市區下拉前先移除。
- 讀取既有訂單時，遇到後台其他付款方式（例如購物金、現金）只略過，不中斷查詢；送單時仍只接受信用卡、ATM、儲值金。
- 新客可填優惠代碼（畫面欄位，或貼上資料中的「優惠代碼：XXX」）。
- 新客／舊客發票都可選捐贈（含捐贈碼，預設 8585）與紙本；貼上資料中的「發票：捐贈 919」「發票：紙本」會自動辨識。
- 新客／舊客都可用「建立筆數」選多個日期或時段，每筆各自呼叫 `quick_create_order`。新客第 2 筆起不再誤判為舊客；改用舊客身份送出時會送出全部筆數。
